# 大学平行时空 University Parallel Universe

## 1. 项目定位

**大学平行时空** 是一个面向高中生的 Web 交互体验项目。

项目通过“选择专业 → 模拟一天 → 做出生活选择 → 生成校园路线和个人画像”的方式，让高中生直观感受不同专业的大学生活节奏。

它的交互形式可以类比 MBTI 测试问卷：用户在一天中的多个时间段做选择，每个选择都会影响若干维度的分数，最终生成一个属于用户的“专业一日体验画像”。

## 2. 核心操作逻辑

项目流程简化为：

```text
进入 Web App
→ 选择一个专业
→ 进入该专业的一日日程模拟
→ 在有限个时间段中做选择
→ 每个选择绑定一个事件和校园地点
→ 根据选择更新多维度分数
→ 在可视化界面形成一天的校园路线
→ 最终总结专业、路线和个人画像
```

本项目不做复杂推荐，也不需要一开始根据兴趣匹配专业。用户先直接选择想体验的专业，这样实现更简单，展示也更稳定。

## 3. MVP 功能范围

一周内优先完成以下功能：

- 专业选择
- 一日日程模拟
- 多时间段事件选择
- 多维度评分
- 事件与校园地点绑定
- 简化校园路线可视化
- 最终画像总结

暂时不做：

- 用户登录
- 数据库
- 自动爬虫
- 机器学习推荐
- 真实地图导航
- 复杂后端
- 大量专业覆盖
- 复杂专业对比

## 4. 专业范围

MVP 阶段建议先做 3 个专业，保证差异明显即可。

推荐首批专业：

- 计算机类
- 医学类
- 经管类

如果时间充足，再加入：

- 法学类
- 建筑 / 设计类

每个专业需要准备一套对应的一日日程模板。

## 5. 一日日程模拟设计

一天被拆分为有限个时间段，每个时间段对应一个问题或事件选择。

建议控制在 5-7 个时间段，避免问卷太长。

示例时间段类型：

```text
早晨
上午
中午
下午
傍晚
晚上
睡前
```

每个时间段提供 2-4 个选项。

每个选项包含：

- 选项文案
- 对应事件
- 对应校园地点
- 对各评分维度的影响

## 6. 评分维度

建议使用 4-5 个维度，保持清晰。

推荐维度：

```text
健康平衡 health
学习投入 study
社交丰富 social
实践探索 practice
压力指数 pressure
```

每个选择会让某些维度增加或减少。

例如：

```json
{
  "label": "去图书馆继续自习",
  "event": "自习",
  "locationId": "library",
  "score": {
    "health": 0,
    "study": 2,
    "social": 0,
    "practice": 0,
    "pressure": 1
  }
}
```

最终根据总分生成用户画像。

画像示例类型：

```text
高专注学习型
均衡探索型
社交活跃型
实践驱动型
压力拉满型
```

## 7. 路线可视化逻辑

每个事件都绑定一个校园地点。

用户每做一次选择，就把该事件对应地点加入当天路线。

最终形成：

```text
宿舍 → 教学楼 → 食堂 → 图书馆 → 操场 → 宿舍
```

为了控制开发难度，MVP 阶段使用 **简化校园地图**：

- 不接真实地图 API
- 用一个自定义平面区域表示校园
- 用固定点位表示地点
- 用线连接用户当天经过的地点

地点数据可以写在 `locations.json` 中。

示例：

```json
{
  "id": "library",
  "name": "图书馆",
  "x": 58,
  "y": 35,
  "type": "study"
}
```

其中 `x` 和 `y` 表示地点在简化地图中的相对位置百分比。

## 9. 页面结构

项目控制在 4 个页面。

```text
首页 / 专业选择页
一日模拟页
路线可视化页
结果画像页
```

也可以把路线和结果放在同一个页面，进一步简化。

### 9.1 首页 / 专业选择页

功能：

- 展示项目名称
- 简要说明玩法
- 展示专业卡片
- 用户选择专业后进入模拟

### 9.2 一日模拟页

功能：

- 显示当前时间段
- 显示当前问题
- 显示选项卡片
- 用户点击选项后进入下一时间段
- 页面上可以显示当前已积累的简要分数

### 9.3 路线可视化页

功能：

- 根据用户选择过的地点生成路线
- 展示地点点位
- 展示地点之间的连线
- 展示用户一天经过的地点顺序

### 9.4 结果画像页

功能：

- 展示用户选择的专业
- 展示五个维度最终分数
- 生成用户画像名称
- 展示用户一天的选择摘要
- 提供重新体验按钮

## 10. 推荐技术栈

为了控制在一周内完成，建议使用纯前端方案。

```text
React
Vite
JavaScript
CSS
本地 JSON 数据
```

不建议一开始做独立后端。

如果老师要求体现“全栈”，可以在项目完成后额外加一个非常轻量的 FastAPI 后端，用来返回 JSON 数据。但 MVP 不依赖后端。

## 14. 主要难点

### 14.1 状态管理

难点：

- 需要记录当前专业、当前时间段、用户选择、分数和路线。

解决方式：

- 所有关键状态集中放在 `App.jsx`
- 暂时不用复杂状态管理库
- 用 React `useState` 即可

### 14.2 数据结构设计

难点：

- 如果选项、分数、地点字段不统一，后续页面会很难对接。

解决方式：

- 先固定 JSON 字段
- 所有专业模板使用同一结构
- 不同成员写数据时必须遵守同一格式

### 14.3 路线可视化

难点：

- 真实地图开发成本较高。

解决方式：

- 使用简化地图
- 坐标用百分比定位
- 用 SVG 或 CSS 连线

### 14.4 AI Coding 整合

难点：

- AI 生成的代码可能风格不一致。

解决方式：

- 每次只让 AI 生成一个组件或函数
- 先定数据结构，再生成代码
- 每写完一个模块立刻运行测试

## 15. 项目一句话介绍

**大学平行时空是一个面向高中生的 Web 专业一日模拟项目，用户选择专业后，通过类似 MBTI 问卷的分支选择体验一天的大学生活，并最终生成校园路线和多维度个人画像。**
